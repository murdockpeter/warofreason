# Expanded regional map (0.17.0)

The simultaneous Fontenoy map can expand from 12 by 8 to **36 by 24 hexes**: 864 playable hexes, nine times the area. Axial coordinates run from q = -12 through 23 and r = -8 through 15. The original q = 0..11, r = 0..7 area stays in the centre. This is an enlarged schematic operating area, not an assertion of measured regional geography or official Maurice mechanics.

New historical campaigns use this extent by default. Existing saves and the original 38-unit creation profile keep their old map until the umpire chooses **Map options ? Expand campaign map** and confirms. Expand during unlocked planning after any preparation is completed. Saved unsealed routes may remain: their coordinates and travel costs are preserved. Archived/concluded games, locked sides and resolution phases cannot expand. There is no silent conversion, shrinking or repositioning.

The expansion adds 768 clear hexes and ordinary non-road connections. Existing terrain, roads, crossings, town/objective/siege locations, scale, HQs, formation assignments, unit identities, source ratings, clock and saved orders are retained. New illustrated woods, towns, waterways and lanes do not automatically become rules data. You can use manual adjudication for agreed outcomes beyond automated movement.

Use **Fit region** for the full overview. Zoom buttons and wheel zoom reveal detail; drag the map with the left or middle button to pan. A drag does not select a formation or append a route step. **Centre on selected** restores normal detail around the selected friendly formation (or an umpire's selection). Arrow keys pan when the map itself has focus, and focusing an offscreen SVG map control brings it into view. Right-click menus and individual route clicks still work. Overview mode hides tiny coordinate labels while retaining named locations. Navigation never commits campaign changes or exposes enemy pieces in faction views.

The regional extent and explicit expansion receipt persist in SQLite, export/import/replay and fresh clones. Old payloads need no schema/export/SQLite migration. Hex/edge limits accommodate the new topology. Campaign file import/export now shares a 64 MiB bound to accommodate larger map snapshots in the journal; reads allocate according to file size and still reject oversized/non-regular files atomically. Long campaign journals remain bounded.

The wider landscape is newly generated scenery, not an enlarged scan or verified map.

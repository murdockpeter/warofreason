# Design decisions

- 2026-10-21: Keep the existing repository root as the application root. Use small local CSS components rather than a large UI framework; Zustand holds only the active screen and transient diagnostic state.
- Use esbuild for explicit main/preload bundles and Vite for renderer assets. Pin installed dependency versions and commit the lockfile.
- License is proprietary/all rights reserved pending owner selection of an open-source license. No rights to Maurice materials are asserted.
- No campaign state or persistence in Milestone A. Diagnostic logs are local app diagnostics, not a campaign event journal. Reset only clears the session diagnostic notice, through a confirmation dialog.
- No provisional rule values or historical deployments have been implemented. Initial unit vocabulary validation follows the supplied plan; full campaign/reference validation belongs to B.
- 2026-10-21: Reload testing exposed Chromium `ERR_ABORTED` (-3) cancellations being reported as fatal load errors. Ignore cancellations and subframe failures; preserve the native alert for genuine main-frame load failures. Real Electron regression checks cover both paths.
- 2026-10-21: A local development screenshot exposed unstyled rendering: Vite injects CSS into style elements, blocked by `style-src 'self'`. Permit inline styles only in the development HTML transform. Production retains external CSS and the strict policy. Electron tests now assert computed flex/grid layout and sidebar color in development, built and packaged runs. The development assertion failed before this fix and passed afterward; the corrected development screenshot was visually inspected.
- 2026-10-21 (B): Use SQLite through bundled `node:sqlite` instead of the originally proposed `better-sqlite3`. Verified directly in pinned Electron 45.0.0 / Node 24.22.0, local Node 24.7.0, and actual packaged app. This avoids a separate native ABI/rebuild dependency. Local Node 24.7 still labels the API experimental; runtime upgrades require the same persistence tests.
- Store versioned validated aggregate snapshots plus relational journal/active-record links. Keep writes, journal insertion and active selection in one transaction. Reject stale revisions; never reset an unreadable or newer database.
- B creates only unconfigured draft campaigns. Scenario data, setup/start actions, dates, forces and house-rule settings remain C or later. Draft-only portable schema v1 is intentionally strict; future versions need explicit migrations.
- Archive is non-destructive and read-only. Cloning creates fresh IDs and a fresh seed, remaps all aggregate references, and records the source ID in a new journal. Import rejects duplicate IDs rather than replacing or silently renaming records.
- Export full saved state and journal via a native dialog, bounded to the same 20 MiB limit as import. Publish using same-directory temporary write, flush and rename. Uncommitted form edits are excluded. No player-facing fog-of-war exports are implemented yet.
- Private PDFs in `contextonly/`, like `reference/`, are ignored by Git and excluded from the package allowlist. They were not needed for persistence work and no source prose or art was incorporated.
- 2026-10-21 (C): Consulted the private Maurice Fontenoy scenario pages for numeric composition and contingent attribution. Encoded French 20, Dutch 7 and Anglo-Allied 11 as scenario-scale facts, with bibliographic references; no prose, images, cards or tactical effects copied. Historical context is corroborated by Royal Collection Trust RCIN 729096. See the sourced campaign specification.
- New campaigns seed a module-0.1.0 draft. Existing v1 drafts upgrade only on explicit module loading; IDs and old journal snapshots remain unchanged. Custom legacy entities are never overwritten. Configured aggregate schema 2 and export format 2 coexist with legacy imports/history; no destructive SQL table migration or bulk save rewrite is needed.
- All provisional opening splits, squares, commander attachments, concealment, schedule, siege defaults and objective descriptions live in the versioned module JSON. They are player-editable house-rule choices. No operational limits, movement costs, scouting tables, siege thresholds or victory rules are implemented.
- The original 12 × 8 SVG is a schematic umpire/setup view. Labels are approximate; no default road/river network is asserted. Proposed roads and scale can change without regenerating square IDs or assignments. Player-specific fog of war and interactive movement remain D.
- Start requires a saved validated setup plus explicit acknowledgement of the provisional setup/map and a default-Cancel native confirmation. Start sets only turn 1 and the chosen opening day/faction. Started setup is read-only; cloning remaps the full graph and creates a draft for new setup review.
